# ADR-0004: Native `.locus` format — RON

- **Status:** Accepted
- **Date:** 2026-11-04
- **Spec:** `docs/SPEC.md §10` (Native file format), closes §12 item 5
- **Issue:** Nerdtisan/Locus#48

## Context

`.locus` is a human-readable text format chosen for clean git diffs and easy debugging (§10). It stores parameters, layers, entities, constraints and regions, plus solved positions so files open instantly. Serialisation must be deterministic (stable ordering), files carry `format_version` with tested migrations in `locus-doc`, and `locus-doc` is a core crate that must build for `wasm32-unknown-unknown` (§3) because the web build opens and saves the same files. The spec names RON with JSON as the alternative.

Both are driven by `serde`, so the document model is the same either way; the choice is about what lands on disk.

## Options

### Option A — RON (`ron` crate)

Rust-shaped notation: struct fields without quoted keys, enum variants by name (`Point(x: 0.0, y: 0.0)`), integer map keys stay integers, trailing commas.

- Pro: smaller and more readable diffs (below); maps keyed by `EntityId` read naturally (`12: (…)`).
- Pro: represents NaN/inf if they ever appear (they shouldn't — see Decision).
- Con: `ron` is pre-1.0 (0.12.3); output details have changed between minor versions before.
- Con: weaker outside-Rust tooling: no `jq`, few editors with schema support, few non-Rust parsers.
- Con: larger wasm code (below).

### Option B — JSON (`serde_json`)

- Pro: universal tooling (`jq`, JSON Schema, every language); stable 1.x crate.
- Pro: smaller wasm code.
- Con: map keys must be strings, so `EntityId` keys become `"12"` while references to the same ID stay `12` — two spellings of one ID in one file.
- Con: externally-tagged enums need an extra object level (`"geom": {"Point": {"x": …}}`); arrays of three numbers explode to five lines; no trailing commas, so appending to a map also changes the previous last line.
- Con: cannot represent NaN/inf (serialises them as `null`, which then fails to load).

Not measured:

- **Total web-bundle impact.** The GUI is not chosen yet (ADR-0001 pending). `eframe`'s `persistence` feature and Bevy's scene format both already use `ron`, so RON may cost nothing extra in the shipped bundle — verify once ADR-0001 lands. Even if it is extra, ~96 KB gzipped is small next to a `wgpu` GUI bundle.
- `serde_json` will be in the desktop binary regardless (MCP is JSON-RPC, §16), but `locus-mcp` is desktop-only, so that doesn't help the web bundle.
- Migration code was not prototyped; the approach below is format-independent.

## Decision

**RON.** On the criterion the spec chose a text format for — readable git diffs (§10) — it wins clearly: about a third fewer lines, diffs that touch only the changed lines (trailing commas), one spelling per ID, and no extra nesting for enum-tagged geometry. Determinism and f64 round-tripping are equal: both are exact for every finite value tested. The costs are a larger wasm parser and weaker external tooling; both are bounded and have mitigations below.

The evidence is moderately close on cost, so **what would change this:** RON turning out to be the only thing pulling `ron` into the web bundle *and* the bundle budget being tight; or a real demand from external tools (non-Rust scripts, other apps) to read `.locus` directly. Either would point to JSON, which the same `serde` model can emit at any time.

Rules that come with it:

1. **Stable ordering:** every map in the document model is a `BTreeMap` (or a `Vec` in a defined order); no `HashMap` in serialised types. Pretty-printing settings are fixed in one place in `locus-doc`.
2. **Finite floats only.** Solved positions and dimensions must be finite; `locus-doc` rejects NaN/inf on save and on load as a structured error. (This keeps the door to JSON open and avoids writing a document that can't be meaningfully solved.)
3. **Pin `ron` to a minor version** (`ron = "0.12"`) and guard output with golden-file round-trip tests (§14), so a `ron` upgrade that changes output shows up as a failing test, not as noisy diffs in users' repos.
4. **Migrations are typed, not text surgery:** read a small header (`format_version`) first, then deserialise into that version's structs and convert step by step (`v1 → v2 …`), each step with a fixture test (§10, §14). This doesn't depend on RON's `Value` type.
5. **JSON stays available as an export view**, not a second native format: `locus-cli` can print a document as JSON for `jq` and scripts, and MCP resources (§16.3) may serve JSON to clients. Loading JSON is not promised.

## Consequences

- `locus-doc` depends on `ron` (MIT OR Apache-2.0, passes `deny.toml`) and is still wasm32-clean.
- §10 now reads RON as decided (no renumbering). The §16.3 "current document (RON snapshot)" resource is consistent; the MCP ADR (0005) may still choose JSON for tool results, since MCP is JSON-RPC.
- Follow-up when ADR-0001 lands: check whether `ron` is already in the chosen GUI's web bundle and record the real size delta.
- The spike in `spikes/file-format/` is throwaway; it is not part of the workspace and is not maintained.
